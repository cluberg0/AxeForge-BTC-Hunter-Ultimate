# AxeForge BTC HUNTER ULTIMATE — Gamma 601

Исходники интеграции AxeForge v1.4.10 для Bitaxe Gamma 601, ESP32-S3, один BM1370. База закреплена: `e84c651c36a4b5f91c537577704245ded032592d`; ESP-IDF **v5.3.2**, commit `9d7f2d69f50d1288526d4f1027108e314e8c879f`. GPL-3.0, см. LICENSE. Исходный пользовательский архив сохранён начальным Git-коммитом; исправления выполнены в собственной ветке.

Итоговый статус и SHA-256 смотрите в **TEST-REPORT.md** и **SHA256SUMS.txt**. Наличие `.bin` означает только успешно скомпилированный и программно проверенный app-образ. Физического Bitaxe в среде разработки нет; аппаратная стабильность, реальный heap, OTA и iPhone Safari требуют проверки по HARDWARE-TEST-PLAN.md. Прирост полезного хешрейта или вероятности блока без измерений не заявляется.

## Возможности

- Русский интерфейс: четыре вкладки, подразделы системы, локальные анимированные фоны, 13 телеметрических графиков/CSV и профили 18/22/30 Вт. Нет внешних ресурсов для оформления.
- Нативная 30-секундная история с PSRAM и ограниченными записями в отдельном NVS namespace; честные пропуски, обработка NTP и ошибок записи без стирания настроек.
- Опциональные охлаждение по ASIC/VRM и возврат к ранее измеренной более низкой точке через штатную задачу тюнера. Отдельного управляющего OC-контура нет.
- Hunter: учёт V1/V1 TLS submit/ACK по исходной сложности/ID/сессии, дедупликация, короткий extranonce2, приоритетная отправка кандидата, диагностика потерянных ответов. SV2 aggregate ACK не выдаются за индивидуальные.
- Benchmark Lab сравнивает только интервалы выдачи работ в уже устойчивом режиме. Напряжение/частота и version rolling не перебираются; результат не применяется автоматически.
- Block Guardian различает локальный target hit, ответ пула и независимое наблюдение сети. Explorer не является собственным Bitcoin-узлом и не доказывает получение награды.
- Pool Intelligence даёт ограниченные рекомендации на основе сопоставимых измерений. Автоматической смены пулов и кошельков нет. Альтернативные coin templates требуют ручной проверки совместимости.

Все экспериментальные функции выключены по умолчанию. Значения 786 МГц / 1170 мВ и пулы пользователя — контекст испытания, не изменённые заводские defaults. Пределы 800 МГц / 1300 мВ и штатные аппаратные защиты сохранены. Номинальные 30 Вт БП не доказывают безопасный непрерывный режим; первый тест — на ранее проверенных настройках с лимитом 25 Вт.

## Установка

Инструкция для пользователя: **INSTALL-IPHONE.md**. OTA принимает только `axeforge-gamma-BTC-HUNTER-ultimate.bin`; не ZIP, не factory, не bootloader и не partition-table. App OTA не стирает NVS, Wi-Fi, wallet/worker и пулы. Новые архивы не входят в штатный backup settings.

## Воспроизводимая сборка для разработчика

Требуются Linux, Git, Python с venv, C/C++ компилятор, make, CMake 3.x, Ninja, Node.js; для host-тестов — headers/libs mbedTLS и cJSON, PyYAML и jsonschema. Для браузерных тестов — Python Playwright с Chromium/WebKit и их системные библиотеки. Это инструменты разработчика; пользователю с iPhone они не нужны.

```sh
bash scripts/bootstrap-idf.sh
export IDF_TOOLS_PATH="$PWD/.tools/idf-tools"
source .tools/esp-idf/export.sh
bash scripts/prepare.sh
bash scripts/test.sh
python3 tests/browser.py
BROWSER=webkit python3 tests/browser.py
bash scripts/build.sh
python3 scripts/stack_report.py
(cd dist && sha256sum -c SHA256SUMS.txt)
```

Если `.tools/esp-idf` уже установлен в другом каталоге, используйте `AXEFORGE_IDF_CHECKOUT` для bootstrap или активируйте собственный ESP-IDF ровно v5.3.2. `prepare.sh` требует отсутствующего upstream, скачивает тег, проверяет точный SHA и применяет все исправления. Не запускайте повторно на изменённом checkout. `upstream/` — воспроизводимая производная, исходные overlay/патчи хранятся в этом репозитории.

`build.sh` сохраняет configure/build/size/image logs в reports, проверяет неизменность source inputs во время сборки, Gamma/BM1370, размер, формат app/board tag, XOR и SHA; экспортирует только app. Одинаковый исходный код собирается повторяемым процессом, но побайтовая воспроизводимость между машинами/датами не заявляется: ESP-IDF включает сведения сборки и пути отладки.

`.github/workflows/build.yml` выполняет те же тесты и сборку, загружает **Gamma-BTC-Hunter-OTA**. Для запуска нужен собственный GitHub-репозиторий с распакованным корнем проекта. В этой сессии удалённый workflow/публикация в GitHub не запускались; готовый локальный комплект предоставляется отдельно.

## Структура и отчёты

- `overlay/`, `apply.py`, `patch_hunter.py`, `integration-hardening.patch`, дополнительные `patch_*.py` — воспроизводимые модификации pinned upstream.
- `base-ui.html`, `prepare_ui.py`, `hunter_ui.py` — входные данные и генераторы итогового HTML. Не подменяйте его старым intermediate.
- `tests/` и `scripts/test.sh` — host, fault injection, независимая математика target, контракты и браузеры.
- `PROGRESS.md`, `CHANGELOG.md`, `TEST-REPORT.md`, `HARDWARE-TEST-PLAN.md`, `reports/` — фактический статус, исправления и доказательства.
- `AGENTS.md`, `TASK.md`, `HANDOFF-TESTS.md` — первоначальные требования и исторический handoff; прежние заявления не заменяют итоговый отчёт.

Полный архив исходников включает пропатченный upstream и исходники интеграции. Зависимости ESP-IDF и component registry воспроизводятся по указанным версиям/lock-файлу; их лицензии сохраняются. Не загружайте личные credentials в исходники или отчёты.
