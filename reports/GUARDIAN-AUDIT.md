# Block Guardian: независимое наблюдение сети

Реализован дополнительный `/api/guardian`, опция `enabled` по умолчанию false. Пользователь явно разрешает отправку **только хеша кандидата** на фиксированный HTTPS endpoint `https://mempool.space/api/block/{hash}/status`. Не передаются wallet, worker, пароли, токены или настройки пулов. Сертификат проверяется штатным CA bundle, redirect запрещён. Произвольный URL задать нельзя.

Запрос выполняет отдельная задача приоритета 2, стек PSRAM 8192 байта. Отправка кандидата на пул ничего не знает об observer и никогда не ждёт HTTPS. Используется копия последнего известного BTC-кандидата Hunter; параметры исходного Stratum-сеанса не изменяются. Новый модуль не отправляет и не повторяет shares.

Каждый запрос ограничен буфером 512 байт, тайм-аутом операции 4 секунды и бюджетом цикла чтения 15 секунд. Первая проверка требует Wi-Fi и синхронизированного времени для проверки сертификата. Частота — не чаще минуты в первый час, затем раз в пять минут; окно проверки ограничено 24 часами. Отключение во время HTTP и смена кандидата отбрасывают старый ответ. Во flash сохраняется только включение, не каждый ответ сервиса.

Состояния API: 0 нет кандидата, 1 ожидает проверки, 2 HTTP 404 (сервис ещё не знает хеш), 3 наблюдение сервиса, 4 ошибка/истекшее окно, 5 отключено. `inBestChain` значимо только при state=3; `height=0` может быть настоящей высотой Genesis, а при других состояниях означает отсутствие текущего результата. `checked` — Unix seconds последней HTTPS-попытки, не число подтверждений. На отказе/истечении подтверждающие поля очищаются. HTTP200 должен содержать настоящий boolean in_best_chain и целую неотрицательную высоту при true.

Telegram/Discord штатно получают отдельное уведомление NOTIFY_BLOCK только при переходе к внешнему наблюдению best chain. Сообщение явно указывает EXPLORER и отсутствие доказательства выплаты. Настройки штатных уведомлений сохраняются.

Важно: это наблюдение одного внешнего сервиса по TLS, **не собственная консенсусная проверка Bitcoin Core**, не криптографическое доказательство включения, не доказательство вознаграждения и не гарантия отсутствия reorg. Пулы не переключаются. Подключение собственного Core/CKPool необязательно; новой внешней инфраструктуры прошивка не требует. До включения сетевых запросов observer нет.

Проверка реального публичного формата: GET Genesis `/api/block/000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f/status` вернул in_best_chain=true,height=0. Это проверяет только совместимость endpoint, не работу ESP32/ASIC.

Host regression `tests/guardian.cpp` компилирует настоящий модуль с детерминированными фейками HTTP/NVS/RTOS и реальным cJSON под ASan/UBSan. Пройдены default-off, NVS failure без применения конфигурации, отсутствие кандидата, offline/NTP, HTTPS конфигурация/redirect/404, Genesis=0, off-best-chain, fractional height, глубокий JSON, ошибка чтения/обрезка/переполнение, OOM клиента, deadline, throttling, смена кандидата и выключение во время запроса, expiry24h и JSON API. Устройство, реальный TLS на ESP32, heap high-water, срок24h и Telegram с пользовательскими секретами не испытывались.
